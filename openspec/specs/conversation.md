# Spec: Conversation Flow

## Purpose

Deliver the end-to-end conversation flow that turns a hold-to-talk gesture into a persisted bilingual turn: record → STT → LLM → TTS → persist message + audio. The flow covers session start (tap a topic card), mid-session barge-in, and session end. This spec is the integration spine of the `chat-mvp` change and binds together `stt`, `tts`, `llm`, `persistence`, `user-profile`, and `audio-waveform`.

## Requirements

### REQ-1: Hold-to-talk round-trip

The system SHALL respond to a press-and-hold on the waveform component by recording audio, dispatching it to STT, invoking the LLM with the transcribed text, dispatching the assistant reply to TTS, and persisting both turns (user + assistant) with their audio paths. The system MUST NOT make any network call during the round-trip.

#### Scenario: Full round-trip persists both messages

- **Given** the user is on the chat screen for the `travel` topic and presses the talk button
- **When** the user speaks English for 3 s and releases
- **Then** the user message is persisted with `stt_audio_path` and `text`
- **And** the assistant reply is generated by the LLM and persisted with `tts_audio_path` and `text`
- **And** the assistant reply is played back via TTS

#### Scenario: Empty or unclear recording does not advance state

- **Given** the user presses the talk button and releases without speaking audibly
- **When** the STT service returns empty text
- **Then** no message is persisted
- **And** the conversation returns to the `idle` state without invoking the LLM

### REQ-2: Barge-in during assistant playback

The system SHALL keep VAD armed during TTS playback. When VAD fires `speech_start` with confidence > 0.6, the system SHALL call `Speech.stop()` within 100 ms, finalize the current assistant turn (persisted with whatever audio path was written), and switch the conversation into record mode. The system SHALL NOT require a button press for barge-in.

#### Scenario: User interrupts — new turn starts immediately

- **Given** TTS is mid-sentence on assistant turn #3
- **When** the user speaks loudly enough to trigger VAD `speech_start` at confidence 0.7
- **Then** TTS stops within 100 ms
- **And** a new user recording begins
- **And** the in-flight assistant turn is persisted with its partial `tts_audio_path`

#### Scenario: Sub-threshold noise does not interrupt

- **Given** TTS is playing and ambient noise stays below the 0.6 VAD threshold
- **When** no `speech_start` event fires
- **Then** TTS continues uninterrupted
- **And** the conversation state remains `speaking`

### REQ-3: Session lifecycle — start, resume, end

The system SHALL create a new `conversation` row when the user taps a topic card from the home screen. The system SHALL resume an existing `conversation` when the user re-opens it from the history list. The system SHALL close the conversation when the user backgrounds the app for > 5 minutes OR taps the explicit "End session" control; closure writes `ended_at` and triggers the auto-summarize hook if the turn count is a multiple of 10.

#### Scenario: Tap topic card starts a new session

- **Given** the user is on the home screen with 8 topic cards visible
- **When** the user taps the `travel` card
- **Then** a new `conversation` row is created with `topic = "travel"` and `started_at = now`
- **And** the chat screen opens with the `travel` system prompt injected

#### Scenario: Backgrounding ends the session

- **Given** an active conversation with 7 assistant turns
- **When** the user backgrounds the app for > 5 minutes
- **Then** `ended_at` is written to the conversation row
- **And** because turn count is not a multiple of 10, no extra summary call is made

## Constraints

- The conversation flow is the integration spine for the `chat-mvp` sub-change; it binds `app/services/{stt,tts,llm,audio,db}.ts` and `app/state/profile.ts`.
- The 5 product defaults are honored end-to-end: persona `"Coach"`, 8 topics seeded, auto-summarize every 10 turns, bundle EN+ES upfront, TTS locale auto-detect.
- Offline-only is non-negotiable: no network call anywhere in the round-trip. `networkBytesSent` MUST equal `0` for every state transition.
- All sub-components MUST be licensed free/open-source: whisper.rn (MIT), llama.rn (MIT), expo-speech (MIT), expo-audio (MIT), op-sqlite (MIT), Zustand (MIT), react-native-svg (MIT), react-native-reanimated (MIT).
- Implemented by sub-change `chat-mvp` (which depends on `bootstrap-toolchain-and-skeleton` and `model-assets`).
